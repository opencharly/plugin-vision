# 2026.313.1958 — feat(schema)!: import the contract's LLM defs instead of restating them

## Summary

`candy/plugin-vision/schema/vision.cue` restated the contract's six shared LLM definitions —
`#LLMSpec`, `#LLMParams`, `#LLMResponseFormat`, `#LLMReasoning`, `#LLMStreamOptions`,
`#LLMNamedToolChoice` — as local twins. The generated `params` package carried `LLMSpec` /
`LLMParams` structs beside them, and `provider.go` bridged the two with a JSON round-trip
(`toSpec` / `toSpecParams`) so the shared SDK `llmkit` client could consume them. One name, one home:
the contract module (`github.com/opencharly/spec/schema`) owns that vocabulary — it is what the
pipeline engine's agent stages author against too, and it generates the `spec.LLMSpec` /
`spec.LLMParams` the client consumes. opencharly/opencharly#950 is the mechanism,
opencharly/opencharly#945 the count.

The schema now imports `schema.#LLMSpec` / `schema.#LLMParams` and declares only its own
`#VisionInput` and `#VisionExpect`. Generation is unchanged and in-process:
`spec/schemaparams.Generate` composes the source as ONE offline CUE module instance (no network, no
module cache, no `cue.mod`, no `cue` CLI) and emits the field through the Go package that owns the
shapes, so `params.VisionInput.Llm` IS `spec.LLMSpec`. With the types identical the bridge is dead
code and is deleted — the endpoint block an author writes reaches `llmkit` as the same value the
contract defines, with no marshal in between.

`spec` and `sdk` are bumped **together** — v0.2026313.1428 and v0.2026313.513. That lockstep is
measured, not stylistic: the older sdk's schema gate compiles the served body with
`cuecontext.New().CompileString(body)` (an import cannot resolve there), and its
`vmshared/spec_aliases.go` re-exports spec types the newer spec dropped.

**Why this repo, of the two the brief offered.** Both carry the same six `dup` rows, but the mirror's
cost is not only the six definitions here: it also forced the JSON bridge above and a parity test that
existed only to keep the copy honest. Retiring it deletes all three. And its surviving surface is small
enough that the equivalence record can be the repo's OWN authored documents — both README examples plus
the org's PR-eval step — where `plugin-pipeline` carries the same six defs behind a much larger surface
(`llm.go`, `contract_test.go`, `llm_conformance_test.go`, and a `ci.yml` projection job). Same first
unit, less blast radius.

### The retired parity test

`schema_parity_test.go` is gone, deliberately, not silently. Its whole job was to keep the local mirror
field-identical to `spec/schema/llm.cue`: it read both texts, parsed each def's top-level field set, and
failed when a field added on the spec side was not mirrored. An import makes drift impossible — the copy
does not exist — so the guard has nothing left to guard, and `schema_test.go` replaces it with the
property that actually matters (the schema composes, the wire carries the import, and both halves judge
the authored documents identically).

It is also worth recording what it was worth while it lived: it **skipped by default**. Its
`CHARLY_SPEC_SCHEMA` override was unset in a normal `go test ./...` run, and its fallback path
(`../../../spec/schema/llm.cue`) resolves to the umbrella's sibling checkout — which does not exist in a
plugin worktree — so the guard was silent unless someone remembered the environment variable:
